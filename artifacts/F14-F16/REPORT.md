## F14 计算口径

- 旧仓历史开仓手续费是沉没成本，不进入增量比较。
- 两个方案使用相同未来持有窗口，并在窗口末平仓。当前盘口不变场景下：
  `增量成本 = 旧仓立即退出成本 + 新仓完整往返成本 − 旧仓窗口末退出成本`。
  两笔旧仓退出成本在该场景中相消，留下新仓完整往返成本；新仓 F10 净收益已经扣掉它，不能重复扣。不是假定旧仓真实平仓免费。
- 换仓条件：`新仓预计资金费 − 旧仓预计资金费 − 增量成本 > 缓冲`。未来基差变化未知，参数缓冲需明确配置，F10 基差压力仍单列，不能把不变盘口场景当保证收益。
- 原仓释放资本 = 现货卖出净额 + 永续已实现价差 + 释放保证金 − 永续退出费用。新仓按该预算和原单笔上限缩量并重新报价；闲置现金按零收益计，禁止挪用其他仓预算扩大换仓。
- 旧仓两腿确认归零后，等待平仓后发起的新扫描；目标净收益还须超过原持有基准和缓冲。目标消失、成本超限或新开失败可留现金并冷却。
- 1000 USDT × 5% / 365 = 0.1369863 USDT/天；4 USDT 成本回本时间 **29.2 天**。
- 次数按已发起换仓计，失败也占次数；冷却按结束时间（尚未结束时按发起时间），UTC 日期划分每日额度。

`--auto-rotate` 默认关闭，要求 `--auto-exit --auto-recover` 和下列六项全部显式提供。首次使用的参数落入账本，变化时阻断以供审阅：

| 参数 | 含义 |
|---|---|
| --switch-min-hold-hours | 原仓最短持有小时，非负 |
| --switch-cooldown-hours | 换仓冷却小时，正数 |
| --switch-buffer-usdt | 增量收益缓冲，非负 |
| --switch-confirm-seconds | 独立确认最小间隔，正数；间隔超过两倍加 5 秒则重新计数 |
| --switch-confirmations | 连续确认次数，正整数；重复快照不增加计数 |
| --switch-max-daily | UTC 每日发起次数，正整数 |

## F15 恢复依据

`recovery_a.py` 重放已确认模拟成交，核对交易/订单身份、终态、数量、逐档价格、成本、手续费、仓位、保证金和现金；资金费核对当期持仓、入账算式及原始率/价格证据。现金允许 1e-8 USDT 的 Decimal 累计舍入差，仓位与成本核对容差为 1e-18。

paper 的 `apply_fill + 清除 pending + 保存成交记录` 是一次原子替换。磁盘全账回放吻合、pending 的订单 ID 不在成交记录内时，仅证明该**模拟意图未入账**：保存原意图到恢复记录，放弃它并释放预留；绝不使用旧盘口补造现在的成交。pending 同时存在成交记录、历史不匹配或未知归属时保持 BLOCK。该规则不适用于真实交易所未知订单。

已知未完成仓位只进入退出，不补开第二腿；已确认归零才能标关闭。正在执行的分配按成交事实收尾，无成交的分配标失败。只自动释放 paper_loop 自己的未执行预留，保留用户手工预留。网络、盘口、精度或资金条件不允许退出时继续保留余量和阻断，不因函数返回或退出码成功宣称平仓。

- `paper_acceptance.py begin` 在开始前冻结观察时长、最大采样/新鲜度间隔、初始账本、代码摘要与实际运行参数。运行参数可在完整 paper_loop 启动参数后加 `--print-config` 导出，该命令只打印配置、不启动循环。
- 准备：`python3 -B paper_acceptance.py begin <新证据目录> --state <paper账本路径> --config <print-config输出文件> --hours <观察小时> --max-gap-seconds <最大间隔秒>`；授权运行时 paper_loop 增加 `--evidence-dir <同一目录>`；查看：`python3 -B paper_acceptance.py assess <目录>`。
- 每轮保存不可覆盖采样、内容哈希命名的账本快照；同一账本内容复用快照。配置或代码变化拒绝混入同一观察期。启动时仅允许一个最大间隔内尚未出现首次成功扫描；持仓检查仍须新鲜。缺样、扫描失联、数据缺口、未满足时长或事件均不能通过。
